# Результаты проверки FoodLab

Проверено 4 ноября 2026 года, в текущей облачной среде. Node.js 24.22.1, Next.js 16.4.5, TypeScript 5.9, установленный Chromium.

| Проверка | Результат |
| --- | --- |
| `npm ci --no-audit --no-fund` | Успешная чистая установка по lockfile |
| `npm test` | 18 тестов прошли, 0 пропущено, 0 ошибок |
| `npm run typecheck` | Успешно |
| `npm run build` | Production-сборка Webpack успешна, проверка типов включена |
| `npm run supabase:start` | PostgreSQL, GoTrue и PostgREST — healthy, схема и RLS применены |
| `npm run test:cloud` | CRUD, два реальных аккаунта, RLS, анонимный запрет, новый вход, защита шлюза и удаление временных аккаунтов — успешно |
| `npm run supabase:backup` | Создан и проверен архив pg_dump с таблицей FoodLab |
| `npm start` | Production-сервер запущен; реальный HTTP и функциональные запросы подтверждены Playwright |
| `npm run test:e2e` | 8 тестов прошли: 4 сценария × настольный и мобильный Chromium, 0 пропущено |

## Что проверяют тесты

Модульные: валидность всех 20 рецептов, суммирование сырых ингредиентов и масла, масштабирование состава/выхода/стоимости, неизменность равной порции, фактический готовый вес и КБЖУ на 100 г, масса штук, вода без калорий, недопустимые числа, повреждённый импорт, агрегация покупок, однократное вычитание запасов, просроченные продукты и разные единицы, отсутствие отрицательных покупок, различие плана и съеденного, фильтрация ограничений, влияние положительных и низких оценок, разнообразие и число порций меню, отсутствие подходящих рецептов, переопределение и скрытие рецептов.

Браузерные: поиск в каталоге, изменение порций (куриное филе 340 → 680 г для 2 → 4 порций), избранное и реакция, добавление в меню, сбор покупок, галочки и сохранение после перезагрузки, создание/правка/удаление запасов и ручных товаров, изменение и сохранение профиля, создание/правка/удаление собственного рецепта, автоплан из 12 порций, запись факта еды, manifest, регистрация service worker и повторное открытие приложения при отключённой сети. Основной сценарий также проверяет отсутствие JavaScript-ошибок и горизонтального переполнения.

Снимки интерфейса: `docs/screenshots/desktop.png` и `docs/screenshots/mobile.png`.

## Диагностированные особенности среды

Turbopack не смог создать служебный сокет (`Operation not permitted`). Выбран поддерживаемый Webpack. Next.js CLI-проверка TypeScript в этом окружении возвращала пустой stdout; в `next.config.ts` включена проверка через API TypeScript. Проверка типов не отключалась.

Хост `images.unsplash.com` заблокирован текущей сетевой политикой. Главная иллюстрация локальная; для недоступных фотографий карточек предусмотрена локальная замена. Работу внешнего фотохостинга в этой среде не заявляем.

В первом прогоне E2E 2 из 6 тестов прошли, 4 выявили неоднозначные доступные названия (цифра счётчика входила в имя пункта меню; одинаковые подписи полей). Названия элементов исправлены. Последний прогон актуальной production-сборки: 6 из 6 прошли.

## Что не проверено и требует настройки

- SMTP, доставка писем, подтверждение почты и восстановление пароля по почте не настроены. Управляемый внешний проект supabase.com не создавался. Собственный экземпляр Auth/PostgreSQL в текущей среде проверен реально.
- Публикация сайта и HTTPS, установка PWA на физический iPhone и Safari. Мобильные проверки выполнены в Chromium с viewport iPhone 13.
- Генеративный ИИ: только контракт адаптера, платный провайдер не подключён.
- Кулинарные испытания, фактические выходы и актуальные цены магазинов. Начальные значения отмечены как оценки.
- Восстановление окружения в новой задаче после публикации снимка: не проверено. Сохранённые install_script/start_skill не являются публикацией.

Приложение работает и с локальным сохранением, и с приватным хранением в собственном Supabase текущей облачной среды. Подтверждены регистрация по паролю, сохранение, новый вход с другого браузерного контекста и изоляция данных. Это не управляемый хостинг supabase.com; доступность сервера зависит от жизни данной среды.


## Подключение собственного Supabase — выполнено

Запущен минимальный официальный стек: `supabase/postgres:17.6.1.136`, `supabase/gotrue:v2.197.0`, `postgrest/postgrest:v14.18`. Три контейнера имеют статус healthy. PostgreSQL хранится в `/workspace/food-runtime/data`. Случайные JWT-секрет и пароль БД созданы программно, не выводились и находятся в файле runtime `.env` с правами 0600. В приложение попадают только публичный anon key и адреса loopback-сервисов. Внешние API предоставлены через ограниченный маршрут `/supabase` приложения; административные маршруты и произвольные REST-ресурсы закрыты.

При первом запуске устранены проблемы bind mount конфигурации и прав SQL-файла; прерванные официальные миграции PostgreSQL завершены. Для текущей версии PostgREST readiness использует отдельный localhost-конфиг. Для BusyBox wget health-проверка Auth явно обращается к собственному loopback без внешнего HTTP-прокси. Внешние сетевые запросы и проверка TLS не обходились.

API-проверка `npm run test:cloud` реально создаёт два аккаунта, проверяет создание, чтение, обновление и удаление документа, запрещённое чтение/запись чужого документа, отсутствие анонимного доступа, запрет административных маршрутов и cross-site-запросов, повторный вход. Временные аккаунты удаляются после проверки. Все проверки прошли.

Новые браузерные тесты подтверждают регистрацию через интерфейс, сохранение имени в PostgreSQL, восстановление после перезагрузки, вход из нового независимого браузерного контекста и возврат к исходному локальному профилю после выхода. В первом прогоне выявлена ошибка сравнения Origin с внутренним адресом Next.js за прокси. Исправлена проверка публичного host; повторный API- и браузерный прогоны прошли. Последний E2E-прогон: **8 из 8**, 0 пропущено.

Резервная копия создана штатным `pg_dump --format=custom`; список архива проверен `pg_restore --list`, наличие таблицы `public.foodlab_states` подтверждено. Это согласованный бэкап, однако полное восстановление на другой машине и публикация снимка этой среды ещё не проверены. Секретный runtime `.env` необходимо сохранять вместе с БД/бэкапом.
